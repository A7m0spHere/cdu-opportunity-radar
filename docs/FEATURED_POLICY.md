# 重要精选规则 v1（Issue #11）

2026-10-22 新增 v3 自动筛选分支：采用有可定位原文依据的模型 selected/not_selected/uncertain 判断，综合重要校园信息范围不变。下面的关键词/权重分支继续用于旧版分析；公开结构保留版本身份，v3 使用 `model_evidence` 理由。详见 [LLM 自动化](LLM_AUTOMATION.md)。

精选是全部质量合格原文的可选子集，不是采集许可、官方重要性认定或当前报名清单。`featured` 可以包含重要历史新闻；`current` 仍只按原文时间、资格及既有规则判断。尚未分析、模型失败和未入选信息继续保留在全部信息及旧 RSS。

## 两个独立维度

客观重要性关注学生权益、学业事务、安全服务、学生参与和有明确依据的重要进展。一条只在一个学院发布的奖助学金或课程调整，也可能入选；来源数量、转载次数、AI 关键词、发布学院大小不加分。

个人相关性由用户选择发布单位、类型、主题、时间及报名状态实现。没有账户、用户画像、偏好持久化或统一“最适合所有人”的排行榜；顺序仍按原文发布日期/首次收录时间，不按模型重要性排序。

## 版本化单模型基线

`FeaturedPolicy` 的版本包含阈值、规则词组和实现哈希。输入来自指定 M7 pipeline 的当前 input_hash；不读取旧 M2 标签、机会 retain/exclude 或人工审批作为入选许可。

1. 质量门禁先决定哪些原文可以展示。分析模块不能放宽来源、正文哈希、撤回及核验时效。
2. 指定 M7 结果必须匹配输入/模型/Prompt/Schema/实现版本，并重新通过原文引用和事实复核。失败、旧版和来源更新不给旧结果兜底。
3. 模型重要性是 `high/normal/low/unknown` 的主观建议，且必须为 inference、附原文短引用和理由。默认阈值 normal。
4. 引用还须命中独立规则阈值（默认 3）；否定/假设上下文不能作为肯定依据。这里只作保守基线，规则有效性仍需新人工基准验证。

| 规则维度 | 本地权重 | 依据示例 |
| --- | --- | --- |
| student_rights | 4 | 学生权益、奖助学金、困难补助、助学贷款 |
| academic_affairs | 4 | 课程/教学调整、补考、学籍、成绩复核、考试报名 |
| safety_service | 3 | 安全预警、紧急通知、停水停电、校园服务变化 |
| major_news | 3 | 原文明示国家级重要进展、重大科研成果、正式获批 |
| participation | 2 | 原文明示报名、招募、征集等参与入口 |
| research | 2 | 一般科研、课题、学术交流 |

权重是可审查的规则阈值，不是模型 confidence 或官方评分。模型为 high 时，权重 2 的参与机会可以入选，但引用必须明确涉及学生，不能把仅限教师的行政报名混入。常规报销、普通工作动态不会仅凭模型 high 入选。模型 low 可形成明确 not_selected；unknown 或缺有效分析保持 pending，不能当负例。

时间/资格仍独立：重要性成立并不证明报名开放。日期用途、资格、AI 政策继续由 M7 确定性校验复核，无依据时展示未知；附件正文未读取时不能推断附件规则。partial 只有独立有效的重要性及引用可继续判精选，失败字段仍为未知。网页摘要保持官方原文节选，不替换为模型自由生成摘要。

## 覆盖与故障

对当前筛选命中的全部合格原文，先统计覆盖，再决定展示哪些精选。`ready` 表示这些信息已有明确入选/不入选决定，允许正常为空；有未分析、运行中或依据不足信息为 `pending`；失败、旧版、失效或队列不可读为 `degraded`，可展示仍然有效的其他精选并提示覆盖不完整。三种状态都不是人工效果验收通过。

接口细分 not_analyzed / in_progress / uncertain / failed，不把模型已完成但依据不足伪装成仍在调用。没有新口径人工标签时 `evaluation_status=human_benchmark_pending`。原始质量门禁失败仍是 HTTP 503，页面隐藏旧数据，与智能降级的 HTTP 200 明确区分。

## 评测与后续

参考 [AIHOT](https://github.com/KKKKhazix/AIHOT) 的可校准选文思路，先保留可解释的单模型分档及证据，不引入双评分、事件聚类或传播热度。标注、固定划分、混淆矩阵与漏报定义见[标注指南](FEATURED_LABELING.md)。不得在 holdout 上反复调 Prompt 或阈值；新模型/Prompt/阈值应产生新的评测记录，保留旧结果。

当前只交付规则与评测工具。用户已明确选择先交付标注表，真实人工 Precision/Recall、代表性和生产效果待后续标注验收；默认 CI 和评测命令不调用模型。
