# 第一次人工标注：一步一步操作

这次要做的事很简单：读一条学校通知，然后记录“我认为这条信息值得推荐给学生吗”，再写一句理由。这叫人工标注。

程序有自己的判断，你有自己的判断。之后评测会比较两者，找出程序漏掉的好机会，以及程序保留但你认为没有价值的通知。这里需要的是你的判断，不是猜程序想要什么答案。

第一次先做 3—5 条，跑通导入，再慢慢完成剩下的。不需要一次填写所有字段，也不需要先学习 AI 或数据库。

## CSV 排版不好看时：先用易读版 Excel

本机已生成 `CDU-人工标注-易读版.xlsx`，保留全部 36 条通知和原始字段，打开时只显示“填写标注”页。列宽、行高、中文表头和下拉选项已经设置好，技术字段放在隐藏的原始资料页，不需要填写。

打开后只做这些操作：

1. 点击该行“打开原文”阅读通知。
2. 黄色区“是否看过”选择“已看”。
3. “值得推荐”选择“是”或“否”；拿不准就留空，并把“还需核实”选为“是”。
4. 在“我的理由 / 疑问”写一句中文说明。
5. 按 Ctrl + S 保存，保持 .xlsx 格式。填完把文件交回，由助手按你实际填写的内容转换成原有 CSV 格式，再使用下面的导入步骤。

这个易读版不能直接传给现有 CSV 导入命令，也不要自行另存为 CSV：中文表头和显示列与机器格式不同。原 CSV 保留作备份，助手转换时会保留 ID、版本指纹和其他原始字段，不替你作判断。

下面仍保留直接编辑 CSV 的完整方法，使用易读版时可以暂时跳过第一到第六步。

## 第一步：找到文件

1. 按 Windows 的 `Win + E`，打开文件资源管理器。
2. 点击窗口上方的地址栏，粘贴下面这段路径，按回车：

   ```text
   D:\AI项目\cdu信息聚合插件\data
   ```

3. 找到 `m2a-labels-2026-10-14.csv`。如果系统隐藏扩展名，你可能只看到 `m2a-labels-2026-10-14`。
4. 复制一份，并将副本命名为 `m2a-labels-my-first.csv`。后续只编辑这个副本，原表作为备份。

`.csv` 是一种普通表格文件，不是程序。副本里有 36 条真实通知，人工判断没有预先填好。

## 第二步：用 Excel 打开，保留原来的文字格式

建议先打开一个空白 Excel 工作簿，再从 CSV 导入，避免日期被自动改成其他格式。

1. 在 Excel 的“数据”菜单中找到“从文本/CSV”，选择刚复制的 `m2a-labels-my-first.csv`。
2. 编码选择 UTF-8，分隔符选择逗号。预览应该能看到正常中文和多列内容。
3. 如果可以直接指定列类型，将所有列设为“文本”。如果只有“转换数据”按钮，进入转换界面；在右侧“应用的步骤”中删除自动的“更改的类型”步骤（如果有），再选中全部列，将数据类型设为“文本”，最后加载。
4. 不同 Excel/WPS 版本的菜单名称可能略有区别。若找不到设置，先不要保存覆盖副本；把遇到的菜单或报错告诉我，再继续。

成功后：第一行是英文列名，从第二行开始每行是一条通知。上方的 A、B、C 等字母是列的位置。

可以调整列宽或隐藏暂时用不到的列，**不要删除列、改第一行的列名或移动列顺序**。

## 第三步：第一次只认这六列

| 位置 | 第一行的列名 | 你要做什么 |
|---|---|---|
| D | `canonical_url` | 阅读用：通知原文网址 |
| E | `title` | 阅读用：通知标题 |
| U | `label_status` | 填写用：这条是否由你看过并作了记录 |
| V | `worth_recommending` | 填写用：你认为是否值得推荐 |
| AF | `needs_further_check` | 填写用：是否还需要核实 |
| AG | `notes` | 填写用：写一句理由或疑问 |

其他列第一轮保持原样：原来是空白就继续空白。尤其不要改 ID、哈希和参考日期/时间。`predicted_` 开头的列是程序预测，先不参考它们，先看原文。

表格很宽时，可按 `Ctrl + G`，输入 `U2`，按回车，直接到第二行 U 列。用同样的方法可以到 `AF2`、`AG2`。看下一条时把数字换成 3，以此类推。

## 第四步：读一条原文，自己作判断

从第 2 行开始：

1. 看 E 列标题。
2. 复制 D 列完整网址，粘贴到浏览器地址栏打开。
3. 看清楚“这是什么活动、谁能参加、何时能报名”。必要时看看原文中的规则或附件；附件不在这张表里自动解析。
4. 想一想：这条信息是否值得推荐给成都大学普通本科生，用来学习 AI、开展实践或进行跨学科创作？

第一轮按下面的标准判断：

- **有参与机会，有学习/实践/创作价值，学生资格和参与时间也能确认**：可以判断为值得推荐。活动不一定要在标题里写“AI”，例如数字媒体、设计、创新实践也可能有价值；是否能使用 AI 要看实际规则。
- **明确只是获奖新闻、普通行政公示、教师/研究生专属活动，或已确定没有可参与机会**：可以判断为不值得推荐。若通知同时有新的招募内容，要按完整原文判断。
- **资格、截止时间、活动内容或参与途径看不清楚**：先记录待核实，不强行填“是”或“否”。缺信息不等于可以参加，也不等于不能参加。

本批表格的参考点是 **2026-10-14 北京时间 00:00**。也就是说，你判断的是“在这个时点是否有机会”，不是你完成编辑的时间。以后继续编辑这批表时不要随手把参考日期改成当天日期。

网页顶部“发布时间”不是“报名截止时间”；“比赛举办时间”也不是报名截止时间。若原网页已经更新、链接打不开或日期存在矛盾，可以先记待核实。

## 第五步：只填四个格子

看完一行，根据你自己的结论填写。下面是通用填写方式，**不是给任何实际通知预设答案**。

| 你的结论 | U：`label_status` | V：`worth_recommending` | AF：`needs_further_check` | AG：`notes` |
|---|---|---|---|---|
| 能确定值得推荐 | `human` | `true` | `false` | 用自己的话写为什么值得推荐 |
| 能确定不值得推荐 | `human` | `false` | `false` | 用自己的话写为什么不值得推荐 |
| 已阅读，但还判断不了 | `human` | 留空 | `true` | 写清楚哪项信息需要核实 |
| 还没有阅读 | 保持 `unlabeled` | 留空 | 留空 | 留空 |

这些英文不用翻译后再填：

- `human`：由人看过并记录。
- `unlabeled`：尚未标注。
- `true`：是。
- `false`：否。

“留空”就是不输入任何内容，不能填“未知”“null”“待定”。第一轮也不要填写其他英文类别。

理由不需要长，能解释你的判断即可。例如，你可以说明自己在原文中确认了什么，或具体缺少了什么信息。不要写自己没有核实过的事实，也不要把手机号或名单复制进备注。

完成 3—5 条就可以先停。剩下的行保持 `unlabeled`，可以下次再做。

## 第六步：保存成 CSV

1. 在表格软件中选择“另存为”。
2. 保存位置选 `D:\AI项目\cdu信息聚合插件\data`。
3. 文件名使用 `m2a-labels-my-first.csv`。
4. 文件类型选 **CSV UTF-8（逗号分隔）**。如果提示该格式只保留当前工作表，确认保存当前这一张即可。
5. 关闭表格软件，确保改动已经保存。

导入的必须是 CSV 文件，不能是 `.xlsx`，也不能把 `.xlsx` 手动改扩展名冒充 CSV。如果 CSV 又被打开编辑，仍要保留全部列和标准日期格式。

## 第七步：把你的判断导入项目

“导入”就是让项目读取你刚填写的文件，保存你的判断。它不会自动发送到 QQ 群。

1. 打开 Windows 开始菜单，搜索并打开“PowerShell”或“终端”。无需管理员权限。
2. 复制下面第一行，粘贴进去，按回车：

   ```powershell
   cd 'D:\AI项目\cdu信息聚合插件'
   ```

3. 再复制下面这一整行，粘贴并按回车：

   ```powershell
   .\.venv\Scripts\python.exe -m cdu_radar label import --db data/m2a.sqlite3 --input data/m2a-labels-my-first.csv --labeler 本人
   ```

`本人` 是记录标注人的名字，可以换成你喜欢的昵称。你输入的判断不会由程序替你改变。

成功后会输出三项数字：

| 输出 | 白话解释 |
|---|---|
| `imported` | 本次新保存了几条人工记录；包含已经看过但待核实的记录 |
| `unchanged` | 几条记录和之前导入的一模一样，没有重复保存 |
| `unlabeled_skipped` | 几条还没阅读，暂时跳过 |

若你确实填写了内容，但 imported 和 unchanged 都是 0，先检查有没有保存 CSV、有没有把 U 列改成 human、命令是不是读取了你编辑的副本。

如果出现报错，不要继续运行评测；先按下一节处理。导入错误会拒绝本次标签写入，不会把一半正确、一半错误的表格混着保存。

## 第八步：让项目比较规则判断和你的判断

在同一个终端中运行：

```powershell
.\.venv\Scripts\python.exe -m cdu_radar evaluate --db data/m2a.sqlite3 --output data/m2a-evaluation-my-first.json
```

先看这些值：

- `valid_labels`：能拿来比较的人工判断数量。V 列填了 true/false、版本有效的记录才参与；“看过但待核实”不会被当成是或否。
- `precision`：程序留下的候选里，有多少比例是你认为值得推荐的。
- `recall`：你认为值得推荐的通知里，程序留下了多少比例。
- `f1`：综合前两项的指标，初次可以暂时忽略。

指标是 0 到 1 的小数，例如 0.5 表示 50%。`null` 表示当前没有足够的数据计算这一项，不是满分，也不是零分。只做了几条时，数字只能帮助找问题，不能证明程序已经可靠。

程序的 retain（保留）和 uncertain（不确定）都会进入候选列表，只有 exclude 才排除。这个评测比较的是“候选是否值得保留”，不是“是否已经批准推送”。

想只看错误，在终端依次运行：

```powershell
$r = Get-Content -Raw -Encoding UTF8 data/m2a-evaluation-my-first.json | ConvertFrom-Json

# 误报：程序保留了，你认为不值得推荐。
$r.error_samples | Where-Object { $_.error_types -contains 'false_positive' } | Format-List

# 漏报：程序排除了，你认为值得推荐。
$r.error_samples | Where-Object { $_.error_types -contains 'missed_opportunity' } | Format-List
```

没有显示内容时，先看 valid_labels 是否大于 0。若为 0，只是还没有有效比较样本，不能说程序没有错误。

## 常见卡点

| 遇到的情况 | 怎么处理 |
|---|---|
| 原文打不开、规则看不懂 | U 填 human，V 留空，AF 填 true，AG 写问题，先做下一条 |
| 不知道该不该推荐 | 同上；不要为了做完表格强行填 false |
| 文件或命令路径不存在 | 检查是否先执行 cd，文件名是否为你保存的副本 |
| `Label CSV columns must match` | 列名、顺序或 CSV 格式被改变；核对原表，不要删除其他列 |
| `expects true/false or blank` | 把“是/否/不确定”等文字改成规定的 true/false 或真正的空白 |
| `Manual values require explicit label_status=human` | 这一行填了判断/备注，却仍是 unlabeled；确认已阅读后把 U 列改成 human |
| 日期格式报错 | 检查 K/L 列是否被软件改成斜杠日期；保持原表里的标准文字格式 |
| `Stale or mismatched notice snapshot` | 数据中的通知版本变了，需要重新导出；保留旧表，不要自己修改哈希来绕过检查 |
| imported=0、unchanged 大于 0 | 同一批判断已经导入过，是正常的重复导入结果 |

发生不清楚的报错时，把终端的报错文字发给我。你的 CSV 保留在本机，不需要重新生成或覆盖已经填写的内容。

第一轮只需掌握“读原文 → 填四列 → 保存 CSV → 导入 → 评测”。需要细分资格、AI 使用政策和时间字段时，再看 [完整字段指南](LABELING.md)。
