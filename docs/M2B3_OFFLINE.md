# M2-B.3 事实校验与字段级降级（2026-10-14）

本轮仅离线修复，新增付费请求 **0**，没有重复调用 ID 34。保留 M2-B.2b 两份未提交文档及全部历史数据。分类、资格、日期分别验证；已验证字段保留，错误字段保存原提议、引用位置、原因和路径，再降为未知。模型分析成功、字段事实核实和人工批准仍是不同状态。

## 三个问题的根因

1. **报名状态**：ID 34 的 `open` 是模型提议，原校验器已经拒绝并输出 `unknown`，并非系统曾将其核实为开放。原文月日未明确年份，模型还列出了年份缺失，结论与自身缺失信息矛盾。原实现日期集中校验并集中清空，不能明确指出哪个日期字段失败；只比较模型提交的日期，也可能漏掉正文另一赛道的不同截止。
2. **资格表达**：原 undergraduate 规则只有“我校/全国等 + 本科生”，未识别“本、专科学生”等协调表达。简单扩词也会掩盖指定院校、专业、地区、年级、推荐与技能条件，因此需要先识别学生范围，再核验资格上下文和全文限制。
3. **字段连带失效**：分类支持以 `student_opportunity=true` 为前置条件，导致参与引用不充分时，正确竞赛分类也被拒绝。日期的集中异常处理会清除其他正确日期。任意引用未定位还会让整条分析失败，未区分可独立降级的日期字段与核心引用故障。

## 实现与契约

`llm_semantics.py` 增加有原因代码的资格验证，覆盖本科生、本、专科学生、本专科学生、全日制普通本科生、在校大学生、普通高等学校在校生。需要报名/参赛对象、面向、可报名等资格语境；获奖报道、否定与条件问句不能仅凭学生名词获得 eligible。

全文中的专业、年级、指定院校、院校类别、地区/户籍、校内推荐、技能和选拔限制仍会让资格待核验。仅限其他具名院校且没有更广范围冲突时，可以支持明确排除；受限但不清楚申请者是否满足时保持 uncertain。没有改 M2-A 的词表来自动扩大规则筛选结果。

新增 `screening_dates.py`，用于 screening_v2 的逐字段日期校验与缓存重验：

- 只接受原文明示年份、可定位的日期和正确用途；不从发布日期、举办日期、当前年份补日期。
- 报名开始、主办方截止、校内截止分别验证，逗号/句号/分号/换行界定用途；同一报名区间仅允许明确共享年份的正确起止端点。
- 正文其他同用途的不同截止、无年份截止或错误日历构成冲突；只用未引用正文检查冲突，不将其自动填入字段。不选最早或最晚。
- 一条日期错误不会清空其他已验证日期；开始晚于截止有字段级冲突记录。
- 状态依旧由程序按参考时点、Asia/Shanghai 和日期精度计算，日期无时分按当地当日结束处理。有未解决的时间限制时阻止 open/upcoming；明确结束的独立证据不被无关错误日期抹掉。

`llm_screening.py` 移除分类对参与机会字段的连带依赖。类别和 AI 相关性有自己的证据规则；类别正确不能替代参与、资格或时间依据。核心字段的虚构引用、身份/Schema 错误仍使分析失败。日期的未定位引用可以独立降级为 unknown：保留 not_found、原提议、错误路径，并保留其他字段；Provider 的 `evidence_ok=false` 如实反映引用定位不完整，不能将它计为完整技术通过。

`NoticeAnalysis` 增加可选的本地契约字段：

| 字段 | 作用 |
|---|---|
| validation_version | 当前事实协议为 `screening-facts-v3` |
| field_validation | 每个核心/日期/推荐字段的 verified、missing、unsupported、unknown 状态 |
| proposed_value / trusted_value | 保留模型原提议与程序认可值，避免默默修改后冒充模型正确 |
| reason / error_paths | 白名单逻辑原因及 `$.opportunity_status`、`$.evidence[n].quote/value` 等具体路径 |
| evidence_indices | 指向保留的证据及其独立引用位置/支持检查 |

多个日期提议在字段摘要并列显示，完整各自值仍在 evidence 中。时间刷新保留原提议，更新可信状态；已核实字段的时间变化标明 `recomputed_at_reference_time`。缓存会校验审计字段与可信值的一致性。

**请求 JSON Schema 未改**：仍为 `llm-screening-v2:dc6d12ad780c`，无需更名配置或数据库迁移。新增的是有显式版本的本地分析元数据；旧序列化记录缺少它们时用 None/空元组读取。Prompt 更新为 `student-opportunity-screening-v2-fields-v4:34222202aa8f`，强调类型与当前可参与状态分开，以及日期用途。新源码、Prompt 和事实协议进入 analyzer 指纹，新旧分析版本不能命中同一缓存或混成一次模型评测。

所有发现的问题仍进入 verification_items，用 value 标明 model_missing_information 或 validator 来源；模型自报事项不冒充校验器的字段错误，但仍要求人工核验。关键依据未成立则推荐保持 uncertain、fact_status=review_required。即使事实全部通过，也只能是 review_status=pending，分析器不能批准发布。不改变人工审批表或其应用方式。
