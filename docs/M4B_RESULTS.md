# M4-B 自动聚合发布验收

日期：2026-10-15，Asia/Shanghai。实现和隔离验证已完成。当前产品入口是 `serve-rss`，通知无需人工审批即可通过质量检查自动进入 `/feed.xml`；详细[运行和契约](AUTO_PUBLICATION.md)。

## 实现与边界

新增 auto_publish / auto_service、独立健康/自动身份表、aggregate CLI、有界定时采集。修改 collect/Store 将逐篇失败即时标记，保留旧正文；采集不再写旧审批状态或事件。旧审批确认写入/导出与旧服务 CLI 停用，历史只读查看保留；新服务的 approved.xml 为 410。HTTP 复用 M3-A 的 OS 锁、SQLite 响应读事务、时效检查和 503，自动状态目录使用独立标识。

本轮在用户指定的原工作区开发，没有合并 M4-A 或 M3-B 分支，也未改生产服务器。开发验收后，用户另行授权 commit,push，使用独立 `codex/m4b-auto-publication` 分支交付，不移动原 M3-B 实验分支。保留开工时四份未跟踪的 M3-B.1 设计草稿；未安装 QQ 插件、实现 OneBot sender、调用模型、扩展来源或开发前端。

新增测试与用户验收的对应关系：

1. 真实裁剪 HTML 经 Mock 官方采集、入库后自动进入 Feed；另有实际定时采集/发布双线程测试，无审核表也可运行。
2. 重复采集只保留同一 URL；原文更新先 503，自动刷新内容，GUID/pubDate 不变；重启仍相同。
3. 过期、校内截止、历史年份/结果、缺年、暂定、多日期、未来报名开始、没有截止都分别覆盖，不把未知当开放。
4. 缺失/非白名单/伪造子域/错误端口/凭据 URL、pending 原文单位被阻止；逐篇解析失败不发布且不删除旧正文。
5. 原文不可用、撤回、撤回后重采、质量状态失效、正文被绕过解析修改、源检查超 72 小时、日期异常均覆盖。
6. 原子写失败、数据库丢失/损坏/WAL、验证超时、旧 ETag 无法绕过 503；读响应持有回滚锁阻止并发提交旧内容。
7. 中文与 HTML/XML 转义、可点击原文、标准 feedparser 消费、摘要正文偏移/hash/quote、未知源发布日期与独立 pubDate 覆盖。
8. 真实历史审批/标签表在自动更新及发布前后逐行一致，旧确认 CLI 不可写；自动路径不加载/调用模型或机器人 SDK。

旧回归中将“采集追加 source_changed 审批事件”改为“历史逐行不变”，将原审批确认成功预期改为退役拒绝，并继续保留只读预览/历史、旧底层版本保护等测试。首次全量运行暴露这些旧行为差异；之后 1 项新夹具缺单位外键已补齐，没有放宽产品来源检查。
