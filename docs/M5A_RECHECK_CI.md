# M5-A 原文复查与离线 CI（Issues #3 / #4）

## 已实现的行为

定时采集先发现新文章，再直接检查到期的已入库原文。新文章发现跳过已收录 URL，所以每轮的 3 篇限制不再反复消耗在首页前三篇；每个来源仍只读取 1 页，不新增全站扫描或翻页爬取。来源起点持久化轮转，预算小或某个官网重定向较多时，后面的来源仍有下一轮机会。

原文检查不依赖通知仍在首页。成功解析后约 24 小时再次到期，按到期时间从旧到新领取，因此接近 72 小时失效的积压条目优先。没有足够依据将报名未知视作已开放，也不按模型评分决定是否复查。积压超过预算仍可能超过 72 小时；到时照常停止发布，不能通过调度承诺覆盖率。

栏目发现与原文核验分别记账：跳过已收录 URL 时仍记录新发现栏目及其日期，不延长原文有效期；直接复查原文只更新正文和健康状态，不覆盖已有栏目的发布日期、首次发现和最后发现时间。

每轮默认 `--request-budget 48`，其中最多一半用于新发现，剩余留给原文复查；robots、重定向与每次重试均计入真实 HTTP 请求数。默认 `--recheck-limit 3`，每来源新文章上限仍由 `--limit` 控制。预算允许 6–500；自动采集仍使用零 HTTP 重试、12 秒超时、至少 2.5 秒间隔，并遵守 robots 的更长间隔。没有到期复查时不借用保留预算扩大抓取。

新增独立表 `notice_rechecks`：状态 pending / running / ready / failed、最后尝试、最后成功、下次允许时间、连续失败次数和错误类别。新旧库迁移幂等，旧健康成功时间原样作为排程依据，不制造新的源检查。`collection_cursor` 只记录下一轮发现来源起点。运行 `serve-rss --collect-interval 0` 仍不启动采集，不需要网络队列初始化。

每次领取使用短 SQLite 写事务，15 分钟领取期限在请求前持久化；网络期间不持有写事务。进程崩溃或重启后到期可恢复；并发工作者不会重复领取未到期的任务。失败依次退避 1、2、4、8、16、24 小时，之后最多 24 小时。成功恢复则重置失败计数。取消或本地预算耗尽仅让任务等待 5 分钟，不修改原文健康状态、不延长最后成功时间，也不缓存虚假的 robots 故障。

原文维护页、410、超时、未知发布单位或身份变化仍执行质量门禁。新 URL 重定向不自动替换旧身份，需核对来源关系；明确撤回不可由后续成功请求自动解除。内容更新与健康版本在同一保存事务中变更；旧 JSON / RSS / ETag 随读门禁失效，先 503 再刷新。GUID、首次聚合发布时间、原始发现时间以及人工标签/审批历史不重写。

## CI 与安装检查

`.github/workflows/offline-ci.yml` 在 PR 和 main push 上运行 Windows / Ubuntu × Python 3.11 / 3.12 四组任务，最小 `contents: read` 权限，checkout 不保留凭据，不引用 secrets，不部署或发布。Actions 固定为已核对的 commit SHA。

各组安装 `.[dev]`、执行 `pytest -q`，再构建并安装 wheel，以 `python -I scripts/ci_smoke.py` 从已安装包检查 CLI 帮助、来源/规则目录和全部网页资源。pytest 默认禁止真实网络连接；需要 HTTP 的测试只允许字面环回地址，官网响应使用 Mock。

CI 不运行真实来源采集、模型 API、QQ、AstrBot、NapCat 或 LAN 预览监听。依赖安装和 GitHub Actions 本身需要联网；“离线”指业务测试范围。Ubuntu runner 通过不代替非生产 Linux 实机运行、长期运行或真实 RSS 阅读器验收。

GitHub 参考：[Python 测试矩阵与安装](https://docs.github.com/en/actions/tutorials/build-and-test-code/python)、[最小权限与固定 Action SHA](https://docs.github.com/en/actions/reference/security/secure-use)。

## 有界真实来源验证方案（本轮未执行）

使用全新的 `artifacts/m5a-live-<时间>` 隔离目录，只选现有 computer 来源，复用生产 Fetcher 的 TLS、robots 和 2.5 秒请求间隔；全程最多 **8 次实际 HTTP 请求**、timeout=12、retries=0，不下载附件。先最多抓 1 个列表和 1 篇详情，记录所有 `request_events` 与真实请求数；失败就保留失败结果并结束，不为得到成功改换更多来源。

成功时在该副本登记一次发布身份，再仅将这条任务的 `next_check_at` 设为当前时间（显式强制排程，不伪造健康成功时间），调用 `recheck` 上限 1。第二阶段只允许已保存原文及其 robots 请求，不读列表；比较健康检查时间、内容、GUID 和首次发布时间。相同 Fetcher 的累计请求上限设为 8；robots 缓存可使正常路径只需约 4 次请求，但不得把预计值当实测值。最终记录请求明细、解析结果、前后版本和身份，不导入用户原库。

这能验证真实官方原文的独立复查；“已退出首页”、维护页、重启、预算不足和故障恢复由离线夹具及隔离 HTTP 回归覆盖，不宣称已经在官网现场观察到退出首页的自然过程。
