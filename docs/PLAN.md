# 开发计划

## M1 实施计划（2026-10-13，修改前制定）

基线：`1e209b4`，工作区干净；49 项 M0 离线测试通过。开发分支 `m1-source-quality`，保持 main 的 M0 可复现状态，本轮不推送。

1. P0 诊断：保存系统 DNS、代理开关、IPv4/IPv6、TLS 和 HTTP 请求的分组证据；仅记录脱敏代理信息，始终验证证书。区分环境连接错误、临时请求错误、访问限制与解析不兼容，失败来源允许下次运行重试。
2. P0 登记：重新获取院系与组织机构目录，区分独立学院、下属单位、中心/平台和部门。只从官方页面观察到的链接登记栏目；对目录中所有单位至少检查官网首页，记录未访问/未发现原因。以 JSON 保留单位关系及多栏目配置，更新人工核查清单。
3. P0/P1 扩展：观察实际列表、详情及分页结构，优先创新创业、美术、影视、药学、师范、电子等，累计争取 6—10 个真实采集栏目。共享已有 HTTP/存储/RSS 模块，新增小型模板适配及裁剪真实样本，不重搭工程。
4. P1 质量：增加页数/文章数上限、明确可信域名和正文路径边界，区分发现栏目与正文发布单位；追加兼容 M0 的 SQLite 字段和链接/附件表，保留原 ID、URL/GUID、首次发现时间。升级前用 SQLite backup 保留本地 M0 数据。
5. 验证：保留全部 M0 测试，新加分页边界、跨来源 URL 归并、迁移、附件及链接、故障分类和 GUID 稳定性回归测试。真实网站验证独立于 pytest，检查解析值和重复采集；不以 HTTP 200 或条目数量代替质量验证。

边界：不做 AI/LLM、复杂截止日期抽取、赛事语义归并、后台、QQ/AstrBot 推送或并发爬虫。公开栏目只做低频、有上限的发现与采集。任何连接失败保留真实证据，不编造样本或验证结果。

## M1 执行结果与 M2 待决策

已完成：本机 DNS/代理/IPv4/IPv6/TLS 诊断及显式公共地址验证；复核 30 个院系条目，扩展为 42 个有来源依据的单位/平台、152 个候选栏目；9 个栏目完成真实采集与重复验证；受控分页、跨学院原文归并、正文链接/附件记录、SQLite 追加迁移和 RSS GUID 保持。M1 数据保存在独立本地库，M0 原库及备份保留，未推送 GitHub。

M2 先明确以下设计，再接入模型：

1. 建立人工标注样本，区分报名/选拔通知、竞赛结果、公示与普通新闻，定义“适合学生参与”和 AI 相关性的依据；覆盖非编程专业和允许使用 AI 工具的跨学科活动。
2. 设计资格、活动状态和截止日期的结构化字段，缺失/模糊日期保留不确定性并附原文证据；不能把历史正文中明显矛盾的年份直接推断为当前机会。
3. 模型仅处理受控样本，正文作为不可信输入，外部链接与附件不成为自动执行指令；发送前处理联系人、名单等个人信息，确定模型服务、成本上限和失败回退。
4. 用人工标注集衡量准确率、漏报、误报与过期通知比例，保持原始记录和分析结果分离，失败时不覆盖原文或既有 Feed。
5. 完善剩余栏目模板和更新时间漂移检测，明确审核后发布 Feed 的契约，再决定 AstrBot 订阅；不直接自动接入生产群。

## M0 原始计划与结果

目标：从两个真实成都大学官方栏目采集原始通知，写入 SQLite，并生成本地 RSS 2.0 技术验证 Feed。

1. 调查（2026-10-13）：检查空工作目录及 Python 环境；读取官网院系设置，登记官网链接；实际检查两个栏目、正文和 robots.txt。
2. 实现：Python 3.12 虚拟环境；httpx + BeautifulSoup 的同步低频请求；两个栏目适配器与共享正文解析；SQLite URL 唯一约束、来源关联、内容哈希更新；本地 collect / export-rss CLI。
3. 离线验证：保存经裁剪的真实 HTML 样本及出处；pytest 覆盖结构变化、请求失败隔离、幂等与更新、日期语义及 RSS 中文转义。
4. 集成验证：每栏目限制少量文章，独立于 pytest；核对标题、链接、日期、正文；重复运行核对记录数；保存可复核的结果到 docs/VALIDATION.md。

边界：M0 不做 AI 判断、赛事级去重、所有学院适配、AstrBot/QQ 配置、服务端公开 Feed 或生产部署。不自动提交或推送 Git。栏目包含获奖新闻、公示等，Feed 不等于有效报名机会清单。

后续优先级：规则筛选和日期/资格抽取 → 小样本人工评估 → 更多模板适配与分页增量 → 赛事级转载去重 → 经过审核后再接入订阅客户端。

## 本轮结果

已实现并验证：两种真实栏目模板、低频 HTTP 请求及日志、SQLite 幂等/更新/来源关联、RSS 2.0 本地导出、49 项离线测试。计算机学院和商学院各实际采集 3 篇，重复采集保持 6 篇，RSS 阅读器解析通过；详见 `VALIDATION.md`。

未完成：优先指定的创新创业学院本机访问持续失败，已登记 failed 并记录请求错误，没有猜测适配器。官网目录已登记 30 个条目，其余未接入；本轮没有宣称全校覆盖。

## 下一轮需求（按优先级）

1. 重验创新创业学院网络连接；取得真实 HTML 后实现并测试该列表及跨学院原文路由，网络恢复前不标记 verified。
2. 建立少量人工标注样本，先用可解释规则区分报名通知、获奖新闻、公示；提取资格和截止日期、识别过期信息，覆盖非编程和跨学科活动。
3. 适配更多实际观察到的学院模板；在严格数量限制内引入分页和增量策略，补充流式响应大小限制及 robots 复杂规则测试。
4. 以已收集样本验证转载的赛事级去重和 URL 规范化，避免将不同轮次或不同校内选拔通知误合并。
5. 在 Linux 上复现安装和采集，补充 CI 并选定开源许可证；通过人工确认 Feed 有效性后再验证订阅客户端，不直接接入生产 QQ 群。

AI 分析、外部来源和正式推送在后续里程碑另行明确，不纳入本轮实现。
